Plugins

One JSON file,
a new mini app on your watch

Mac Watch plugins are purely declarative manifests: metadata, page components, settings, and HTTP actions live in one JSON file. Import it and it runs — no code required.

Declarative JSON HTTP + JSONPath 14 content components State persists locally {{template}} variables AI prompt included

Quick start

Run your first plugin in three steps

01

Create the manifest

Copy the AI prompt below into any AI and add one line describing what you need; or configure and export <id>.json with the online builder. You can also download a Manifest V2 example plugin — including its explicit permission declarations — and tweak its fields.

02

Import into Mac Watch

Crown-click to open the Honeycomb → Plugin Manager → Import at the top right: pick a JSON file or paste the manifest text. Re-importing the same id overwrites and reinstalls.

03

Open it from the Honeycomb

The plugin appears in the Honeycomb — tap to open. The first HTTP action runs automatically on open to fetch data, and you can configure periodic refresh.

1. Top-level fields

            
A plugin is a JSON object holding metadata, pages, actions, initial state, and a refresh policy:

            

              

                
FieldTypeRequiredDescription

                
                  
idStringYesUnique identifier. Starts with a letter/digit, only A-Z a-z 0-9 . _ -, ≤ 100 chars; reverse-domain recommended, e.g. com.example.stock

                  
nameStringYesDisplay name in the Honeycomb and page headers

                  
versionIntYesInteger version, starting at 1

                  
iconStringYesSF Symbol name; every reference is validated at import — invalid symbols are rejected

                  
colors[String]NoHoneycomb icon gradient, two hex colors; gray when omitted. Supports #RGB / #RRGGBB / #RRGGBBAA

                  
backgroundObjectNoPage background: solid / gradient / image; defaults to the app background

                  
stateObjectNoInitial state key/values (strings / numbers / booleans); edits persist on this Mac

                  
refreshIntervalDoubleNoAuto-refresh in seconds, effective at ≥ 5; no timer by default

                  
loadOnStartBoolNoRuns the default refresh action when the plugin opens · defaults to true; set false for manual only

                  
permissions[Object]Manifest V2Explicit capability grants. Each item is { "capability", "scope", "required" }; capabilities are networkRequest, clipboardWrite, openURL, mediaControl, nativePage, remoteImage, and autoRefresh. Host scope accepts an exact domain or a parent domain.

                  
pagesObjectYesPage table keyed by page id; main is the entry page, the rest are navigate sub-pages

                  
actionsObjectYesAction table keyed by action id, referenced by buttons / trailing controls / auto refresh

                
              

            

          


          

            
2. Pages & headers

            
Every page (PluginPage) has four parts: a header, a body component array, an optional settings section, and optional bottom buttons. Pages render on one of five layout templates (see the layout model below) selected by the layout field.

            

              

                
FieldTypeDescription

                
                  
headerObjecttitle (required), icon (optional), trailing[] (optional, right-side controls)

                  
bodyArrayBody components, see next section; may be empty

                  
settingsArraySettings controls that write back to state on change; optional

                  
bottomArrayBottom buttons; optional

                  
layoutStringLayout template of the app's unified page system; an explicit value overrides fit. hero · scrolling flow — header / body / settings / bottom scroll as one page (default); heroFull · first screen pins — header / hero / bottom always fill screen 1, settings start on screen 2; fit · one-screen adaptive center, no scrolling (equals fit: true); list · fixed header + scrolling center, bottom buttons flow at the end of content; pinned · fixed header + scrolling center + bottom bar pinned — buttons never leave the screen. Omitted = automatic: fit:true → fit, otherwise hero

                  
fitBoolLegacy shorthand for layout: "fit": true = fits one screen (FitPage) — the center doesn't scroll and content adapts; defaults to false with overflow scrolling + a breathing collapse arrow. Prefer the explicit layout field

                  
nativeStringNative page marker (currently whitelists music): renders the built-in Music app for the whole page (QR login / grid / player), identical to the native one — the plugin is just an entry point

                
              

            

            
Header trailing controls trailing come in three kinds:

            

              

                
typeFieldsBehavior

                
                  
buttonicon, actionTap runs the action; shows a loading state when it is the default refresh action

                  
togglebind, iconOn, iconOffSwitch bound to a state key; swaps icons with the value

                  
textbindRead-only display of a state value

                
              

            


            
Layout model

            
Every plugin page runs on the app's unified watch layout system — the same five skeletons the built-in apps use (plus a native shortcut). Set one with the layout field. All templates obey two principles: the first screen always fits (nothing clipped or overflowing), and content below the fold is hinted by a breathing arrow in the bottom-right corner wherever scrolling exists.

            

              

                
layoutModelBest for

                
                  
hero · defaultType 4 scrolling flow — header / hero / settings / bottom scroll as one page; the hero centers when content fitsDashboards with a focal metric + a settings tail (weather, rates)

                  
heroFullType 4 first-screen-pinned — header / hero / bottom always occupy screen 1; settings start on screen 2Immersive hero pages that keep controls on a second screen (health, interpreting)

                  
fitType 5 one-screen — adaptive center that never scrolls; text auto-shrinks, rings / QR codes fill the centerSingle-purpose pages (hitokoto, QR code, a lone counter)

                  
listType 3 — fixed header + scrolling center; no pinned bar, bottom buttons flow at the end of contentLong feeds where buttons belong to the content tail

                  
pinnedType 2 — fixed header + scrolling center + bottom bar pinned on screenAction-heavy pages: the primary button never scrolls away (repo radar, exchange)

                
              

            

            

              
              
              
            

            
    
              
  • Picking a template: layout maps one-to-one onto the skeletons the built-in apps use — start from the table above; omitted, the app falls back to fit:true → fit, otherwise hero.
    • 
              
  • Scrolling templates (hero / heroFull / list / pinned): when content overflows, the breathing fold arrow appears (hidden while everything fits, ↓ while there is more below, ↑ once you reach the end). On pinned and heroFull, only the center region scrolls — header and bottom stay put.
    • 
              
  • One-screen fit page (fit): the center never scrolls — content adapts instead. Text auto-shrinks down to 50% to stay fully visible, and rings / QR codes / images fill the center area.
    • 
              
  • Sub-pages, never popups: navigate switches pages full-screen and the header gains a back arrow — the app has no alert popups at all. Destructive bottom buttons use double-tap confirm (first tap turns red + shake) instead of a dialog.
    • 
              
  • Header overflow guard: more than two trailing controls collapse the leading ones into a glass ⋯ menu — put your high-frequency actions last in the trailing array.
    • 
            

          


          

            
3. Body components

            
body is an array of components distinguished by type. Text comes from either value (a literal supporting {{key}} templates) or bind (reads state; an np. prefix reads the built-in player live) — pick one.

            

              

                
typeFieldsDescription

                
                  
textvalue / bind, style, colorText. style: normal · hero (large) · caption (small); color: default · accent · warning · gradient

                  
metricvalue / bind, unit, style, animatedBig number (rates / counters). unit appends a unit; style defaults to hero; animated: true adds a rolling-number animation + monospaced digits

                  
iconvalueLarge SF Symbol

                  
listbind, titleKey, subtitleKey, valueKey, emptyText, onTap, progressKey, progressMaxReads a state array into list rows. onTap: {page, prefix} writes the tapped element's fields to prefix.* (plus _index / _total / posFrac) then navigates; progressKey adds a usage bar per row (progressMax defaults to 100, shown as a percent)

                  
progressvalue / bind, label, detail, showPercent, max, thresholdsProgress bar, value 0–1. With label / detail / thresholds it renders in the AI-usage style (label + percent row / tri-color capsule bar / detail row); thresholds: {warning, critical} turns orange / red past the limits

                  
ringvalue / bind, label, showPercent, max, thresholdsLarge ring in the AI-usage home style: trimmed ring + center percent / label; fills the center on fit pages, fixed size on scrolling pages

                  
statsitems[]Three-column stat grid (weather-page style): each cell icon + value / bind + caption

                  
sparklinebindMini line chart: reads a numeric array, normalized with a gradient fill

                  
countdownvalue / bind, labelCountdown: target supports ISO8601 or unix seconds / millis, self-driving every second

                  
tagsbind or values[]Pill tags: reads a string array (or literal), auto-wrapping grid

                  
imagevalue / bindRemote image: downloaded and cached locally (plugin-assets), cover-fit rounded corners + highlight stroke

                  
qrvalue / bindQR code: fills the center on fit pages, fixed size on scrolling pages

                  
spinnerbindLoading indicator: bind reads a boolean (np.isLoading works out of the box), shown when true; always shown when omitted

                  
divider—Divider line

                
              

            

          


          

            
4. Settings

            
The settings section lives in the extras area; controls read and write state keys directly via bind, changes persist immediately, and HTTP action {{key}} templates always see the latest values.

            

              

                
typeFieldsDescription

                
                  
pickerlabel, bind, options[]Single-select dropdown; options are a string array

                  
stepperlabel, bind, min · 0, max · 100, step · 1Numeric stepper

                  
togglelabel, bindBoolean switch

                
              

            

          


          

            
5. Bottom buttons

            

              

                
FieldDescription

                
                  
label / iconText and SF Symbol; provide at least one

                  
actionAction id run on tap

                  
styleprimary · solid accent; plain · glass; danger · red (destructive semantics)

                  
confirmtrue = double-tap confirm: the first tap turns it red for 3 s, the second executes — the no-alerts guard against accidental taps

                
              

            

          


          

            
6. Actions

            

              

                
typeFieldsBehavior

                
                  
httpmethod · GET, url, headers{}, body, extract{}HTTPS request (15 s timeout) gated by scoped networkRequest; url / headers / body support {{key}} templates, and extract writes the response into state by JSONPath

                  
setvalues{}Writes several state key/values in place

                  
copytextRenders the template, then copies to the clipboard; requires clipboardWrite

                  
open-urlurlRenders the template, then opens the HTTPS URL in the default browser; requires scoped openURL

                  
navigatepageNavigates to another page in pages; the header gains a back arrow

                  
mediacommandControls the built-in player: toggle (play / pause) · next · prev; works with any loaded music source queue and requires mediaControl

                  
appproviderOpens a native music source page: local · netease · qq · kugou; requires nativePage. The last three are community-edition capabilities; the App Store build gracefully degrades to a notice

                
              

            

            
JSONPath: extract values are dot paths with array indexes, e.g. $.rates.CNY, $.list[1].n; unresolvable paths write null for that key.

          


          

            
7. Runtime semantics

            
    
              
  • Default refresh action: the first http action (otherwise the first action). Runs once when the plugin opens with loadOnStart ≠ false; repeats on a cycle when refreshInterval ≥ 5 seconds.
    • 
              
  • Template variables: {{key}} is replaced with the current state value (numbers and booleans stringify directly); keys missing from state stay as-is, which makes step-by-step debugging easy.
    • 
              
  • Player data source np.*: a bind starting with np. bypasses plugin state and reads the built-in player live (np.title, np.artist, np.playlist, np.cover, np.isPlaying, np.isLoading, np.index, np.total, np.currentTime, np.duration, np.progress, np.timeText); read-only — set / extract / settings / list onTap prefixes cannot write to it.
    • 
              
  • Layout semantics: layout picks one of the five unified templates (hero · heroFull · fit · list · pinned); scrolling templates show a breathing fold arrow on overflow (↓ more below, ↑ at the end), fit forces a one-screen adaptive center, and pinned keeps the bottom bar always on screen.
    • 
              
  • State persistence: state is written to local UserDefaults on first change (key plugin.state.<id>) and survives app restarts; Plugin Manager can reset it to the initial values.
    • 
              
  • Feedback: a glass loading state shows while a request is in flight; failures surface a notice under the header that clears automatically on success.
    • 
            

          


          

            
8. Install & manage

            
    
              
  • Location: ~/Library/Application Support/Mac Watch/plugins/<id>.json; you can also drop files in manually — Plugin Manager scans the folder automatically.
    • 
              
  • Importing: Plugin Manager → Import at the top right → pick a JSON file or paste the manifest text; the filename doesn't matter — the manifest's own id decides what lands on disk.
    • 
              
  • Overwrite & uninstall: re-importing the same id overwrites and reinstalls; Plugin Manager supports deleting and hiding from the Honeycomb (visibility is just a hidden list).
    • 
              
  • Built-in examples: Exchange Rates, Hitokoto, and the community-build Now Playing entry are seeded on first launch — modify or delete them freely. Every example manifest declares its permissions explicitly.
    • 
              
  • Community shares: the community examples below import directly; share your plugin JSON as a code snippet — the best ones get collected here.
    • 
            

          


          

            
9. Security & validation

            
    
              
  • id whitelist: must start with a letter/digit plus A-Z a-z 0-9 . _ -, ≤ 100 chars; path traversal (e.g. ../evil) and symbol-only ids are rejected.
    • 
              
  • Web protocols only: Manifest V2 network requests, remote images, and open-url destinations require https://; local schemes such as file:// are always rejected.
    • 
              
  • Explicit permissions: import shows every declared capability before anything runs. Network, remote-image, and open-URL scopes restrict requests to the exact host or a declared parent domain; authorization can be revoked at any time and permission changes invalidate old authorization.
    • 
              
  • Auto-refresh gate: loading on open or refreshing on a timer requires both networkRequest and autoRefresh.
    • 
              
  • Icon validation: every SF Symbol reference in the manifest (header, trailing, body, bottom buttons) must exist in the current system symbol set, or the import is rejected.
    • 
              
  • Data boundary: state stays on this Mac and is never uploaded; requests time out after 15 s, and a failure never affects other plugins.
    •
